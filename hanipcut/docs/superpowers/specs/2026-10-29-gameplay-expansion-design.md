# 한입컷 게임 확장 설계 및 체크리스트

사용자 요청: 설계 → audit → 구현 → audit. 각 audit gate는 **85/100 이상**, 중대 결함 0건이다. 기존 Canvas 2D/순수 JavaScript 및 웹·토스·PWA 배포 구조를 유지한다. 별도 배포나 외부 보상 지급은 이 작업에 포함하지 않는다.

## 요구사항 체크리스트

- [x] 1~3단계 시간을 10/10/8초에서 **30/30/24초**로 늘린다.
- [x] 광고 이어하기는 **한 판 3회**, **하루 무제한**이다. 광고 실패·중도 종료는 차감하지 않으며 중복 요청을 막는다.
- [x] 하트·코인·부스터 재고를 저장하고 화면에 표시한다.
- [x] 연승 도전의 **3·6·9·12…번째 판**에만 4단계(7조각, 6회 자르기)를 추가한다. 첫 두 판과 그 밖의 판은 3단계다. 4단계 기본값은 24초, 통과 75점, K=1.5, 속도 가중치 0.1이다.
- [x] 드래그한 **자유곡선 전체 경로**를 그리기·면적 계산·조각 분리 연출에 동일하게 사용한다. 끝점 사이 직선으로 대체하지 않는다.
- [x] 취소: 유효한 직전 선 한 개를 제거하고 자르기 횟수를 복구한다. 시간은 되돌리지 않는다. 마지막 선 이후에도 취소할 수 있도록 **판정하기** 버튼으로 확정한다(튜토리얼만 기존 자동 판정).
- [x] 도우미: 음식의 알파 면적을 기준으로 같은 면적이 되도록 계산한 **실선** 가이드. 현재 판의 다음 단계에도 유지하며 판 성공/실패/이탈 시 종료한다.
- [x] 스탑워치: 현재 단계의 남은 시간 고정. 다음 단계·재시도에는 해제한다. 이미 작동 중이면 재소비하지 않는다.
- [x] 돋보기: 드래그 중 잠정 조각 면적 % 및 확정 선의 면적 %를 표시한다. 도우미와 같은 판 범위를 갖는다.

## 설계자가 정한 기본 경제 규칙

요청에 수치가 없어 정한 조정 가능한 기본값이다. 기존 토스포인트(`S.points`, 지급 API)와 게임 코인은 별개다.

- 첫 지급: 하트 5, 코인 50, 각 부스터 1개.
- 하트 상한 5, 20분에 1개 자연 충전(비접속 시간 포함). 하트 1개로 실패한 단계 재도전. 게임 시작에 하트를 요구하지 않는다.
- 코인 보상: 한 판 전체 클리어 20개, 4단계가 포함된 판은 10개 추가. 중복 클릭/재호출로 중복 지급되지 않는다.
- 구매: 하트 1개 30코인, 취소 10, 도우미 30, 스탑워치 20, 돋보기 30. 상점에 설명과 가격·보유량을 표시한다.
- 재고는 사용 가능할 때만 1개 소비. 빈 재고·취소할 선 없음·이미 활성·카운트다운·판정 중·튜토리얼에서는 소비하지 않는다.
- 기존 저장 데이터에는 누락 필드만 기본값을 넣는다. 빌드 ID가 바뀌었다는 이유로 기존 저장을 초기화하던 테스트 동작을 제거한다. `?reset=1` 및 수동 초기화는 유지한다.

## 구성과 데이터 흐름

- `bb/src/game-core.js`: DOM 없는 순수 규칙(판별 단계 수, 경제/재고, 자유곡선 면적 계산). Node 기본 테스트 러너에서 직접 테스트한다.
- `bb/src/game.js`: 포인터 경로, 화면, 아이템 수명, 이어하기 동시 실행 방지, 판 완료 보상 연결.
- `bb/src/index.html`, `style.css`: 하트/코인 HUD, 상점, 네 아이템 툴바, 판정 버튼. 기존 음식/게임 분위기를 유지한다.
- `bb/build.py`, `pwa/build.py`: 공통 core를 game.js보다 먼저 포함한다. 토스 빌드는 웹 빌드를 재사용한다.

## 자유곡선 판정

음식 사각 영역 전체(투명 배경 포함)에서 이웃 픽셀 사이를 드래그 선분이 가로지를 때 연결을 차단하고 영역을 flood fill한다. 면적 합산에는 알파 마스크 픽셀만 포함한다. 음식 픽셀을 지우지 않아 총면적이 보존되며 원래 떨어진 음식 장식도 같은 절단 영역이면 합산한다. 경로 끝점이 투명 배경에 있으면 **음식 픽셀을 하나도 지나지 않는 BFS 경로**로 사각 영역 바깥에 연결한다. 연결은 음식 없는 곳에만 생겨 그리지 않은 음식이 잘리지 않는다. 외부에 연결되지 않은 구멍(도넛 중앙) 끝점은 확장하지 않는다. 도넛 구멍에서 바깥으로 그은 한 줄처럼 조각을 나누지 못한 슬릿은 횟수를 소비하지 않는다.

교차선·닫힌 고리도 같은 방식으로 처리한다. 짧은 탭, 음식에 닿지 않는 선, 조각을 추가하지 않는 선은 소비하지 않는다. 음식 내부에서 끝난 미완성 경로는 자르지 않으며 완전히 닫힌 고리는 허용한다. 1.5% 미만 부스러기는 목표 조각 수에서 제외한다. 미리보기는 최대 초당 약 12회 계산하고 결과를 캐시한다. 단일 활성 포인터만 사용하며 취소/캡처 소실/팝업/화면 이탈 시 경로를 폐기한다. 판정의 동일 label map으로 각 조각 알파 이미지를 만들어 분리 연출한다.

## audit 보완 및 수명·동시 실행 규칙

- 4단계 주기는 누적 플레이 수가 아닌 `G.stageNo`를 사용한다. 표시·최종 단계 판정 모두 해당 판의 단계 수를 따른다.
- 도우미/돋보기: 단계 성공에는 유지, 첫 실패/최종 성공/홈/새 판에 종료. 스탑워치: 다음 단계와 광고/하트 재시도에도 종료.
- 광고: 전역 진행 잠금 + flow 토큰 검사. 시청 완료 후에도 원래 실패 화면이 유효한 경우에만 이어하기/차감한다. 하루 횟수 저장은 제한 조건에서 제거한다.
- 코인 완료 보상은 첫 실패에서 이미 바뀌는 `playCounted`와 별도인 `roundRewarded`로 보호한다. 결과의 다음 버튼도 한 번만 처리한다.
- 취소는 불변 경로 배열에서 마지막 경로를 제거하고 preview·mask·chip 캐시를 폐기한다.
- PWA는 기존처럼 reset 쿼리와 수동 초기화 코드를 빼고 저장을 유지한다. 기존 bestStage → bestClear 마이그레이션을 보존한다.
